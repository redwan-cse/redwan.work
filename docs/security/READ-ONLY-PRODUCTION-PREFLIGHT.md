# Read-only Production preflight

Owner authorized careful use of GitHub Environment Production credentials for read-only verification. This is separate from disposable tests. No application build/install/test process receives these credentials. The preflight is dependency-free Python standard library, with explicit HTTPS hostname/path/method allowlists, bounded in-memory responses, no redirects, no subprocesses and no dynamic code evaluation. A reviewed exact source commit is pinned by its workflow before any secret-bearing step.

Allowed network operations: public Supabase JWKS GET; secret-key REST queries selecting id with limit0 from profiles/email_outbox (no customer rows); Supabase Management GET of the configured project's auth configuration; Resend GET /domains; per-bucket R2 signed HEAD and GET CORS configuration. Each credential goes only to its corresponding provider. Configured Supabase/R2 URLs must match canonical hosted-provider domains. Unexpected/custom domains fail closed rather than receiving credentials. No objects/users/emails are listed or downloaded; no SQL query API is called.

Auth config is held in memory and reduced to exact site-origin match, SMTP field presence and exact recovery-template link-shape compatibility. These are static configuration checks, not delivered mail proof. Resend sending-only credentials can legitimately deny domain-list access: do not expand their permissions just for this probe. R2 HEAD/CORS metadata access may be denied to object-scoped credentials and does not prove PUT/DELETE capability. CORS PASS means a matching origin/PUT/content-type rule was seen, not full hosted upload acceptance. CDN check is configuration equality only, not object retrieval.

Only fixed probe labels and PASS/FAIL/MISSING/INVALID/DENIED/UNAVAILABLE/UNKNOWN/NOT_CHECKED/RESTRICTED codes are printed or saved. No raw responses, keys, URLs from providers, object names, customer rows, Auth SMTP passwords or error bodies enter logs, artifacts or commit statuses. The safe report is stored under runner temporary storage with mode0600 and is not uploaded as an artifact. A separate reporting step may publish these fixed categories using only the GitHub token, without production credential environment mappings.

Intentionally NOT checked: production backup/restore, migration ledger/upgrade rehearsal, actual Vercel deployment variables, active Cron/Vault equivalence, Google/Blogger or Turnstile credential validity, Resend send permission/delivery. Those require separate bounded probes or explicit write approval. CRON_SECRET is not passed to this workflow and no cron/outbox endpoint is invoked: even GET can cause mail sending or deletion. No reset, migration, user creation, mail, upload/delete, scheduler activation, PR merge or app deployment. GitHub may record environment-job deployment metadata; this does not deploy application code.

The workflow is one-shot on a change to its own path on the exact named remediation branch, never a pull_request or pull_request_target secret consumer. Environment reviewer/branch restrictions are respected. Existing untrusted build/test workflows are not bound to Production. Before future preflight changes, repeat synthetic safety tests and pin the newly inspected source commit.
