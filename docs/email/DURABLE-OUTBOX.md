# Durable lifecycle outbox

Migration 0022 captures CRM lifecycle events in the same database transaction as the business mutation. Ticket creation, replies, manual status transitions, deliverables, sent invoices and confirmed payments no longer depend on a floating promise surviving the response. A rollback leaves neither the business mutation nor its email event. One recipient event is persisted per active admin, or one client; missing recipients are visible failed events. Auth-owned credential-bearing invitations/recovery remain outside this CRM event stream.

A service-only claim RPC leases one event with SKIP LOCKED and a random fencing token. The worker persists an immutable rendered envelope before contacting Resend and uses lifecycle/event-id as the stable provider idempotency key. Ambiguous provider timeouts retry the identical envelope/key. Outcomes and email_log are committed together through the fencing-token RPC; failed audit writes leave the lease recoverable. Attempts are bounded at five, and no automatic send is retried beyond 23 hours from the first attempt, inside the provider's documented 24-hour idempotency horizon. Accepted means provider accepted, not inbox delivery. Bounce/delivery webhooks remain an explicit integration boundary.

Inactive recipients are suppressed by default rather than mailed private content. Email origin must be an explicit configured HTTPS origin (loopback HTTP for disposable tests only), never request-derived. No provider diagnostic payloads, email HTML or tokens reach logs; existing access-controlled recipient audit rows and private outbox envelopes remain personal data requiring the owner's retention policy.

GET /api/cron/email-outbox is bearer-gated and drains at most three events per invocation. A production scheduler cadence is not silently chosen: Vercel plan/frequency and the owner-approved sending/retention policy are rollout prerequisites. Event persistence is independent of scheduler availability, and the admin queue viewer exposes backlog and failures. Legacy request-time send helpers must be gated before this worker is enabled to avoid double-sending; this branch includes that integration step and tests before release.

No production migration or actual mail was sent by development tools. Required acceptance: rollback/event cardinality, concurrent leases, retry fencing, immutable envelope/idempotency, provider timeout/rejection, inactive recipients, audit failure and actual disposable transport. Production activation additionally needs independently reviewed migration, verified backup and exact owner approval.
